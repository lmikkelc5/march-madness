# My attempt at predicting future march madness tournaments using past data.

Data is scraped from sports-reference.com and stored in a local SQLite database, then (eventually) used to build a prediction model.

## Top level

### `config.py`

Shared config for the project. Currently just resolves the project root and defines `DB_FILE`, the path to `database/march_madness.db`, so every script can point at the same database file without hardcoding paths.

### `main.py`

Placeholder entry point generated by the project template. Not wired up to anything yet — the real pipeline is run through `scripts/update_all.py`.

## `scripts/`

### `scripts/create_database.py`

Builds the SQLite schema. `delete_database()` removes the existing `.db` file so it can be rebuilt from scratch, and `create_database()` connects (creating the file if needed) and creates two tables:

- **`teams`** — `team_id`, `school`, `slug` (lowercase, URL-safe name), `url` (path to the team's page on sports-reference.com).
- **`team_seasons`** — one row per team per season, keyed by `team_season_id` with a `UNIQUE(team_id, season)` constraint and a foreign key back to `teams`. Holds win/loss record (`games`, `wins`, `losses`, `win_pct`), rating metrics (`srs`, `sos`), scoring (`points_per_game`, `opponent_points_per_game`), and full season shooting/rebounding/box-score totals (`minutes`, `fg`/`fga`/`fg_pct`, `three_pt`/`three_pt_attempts`/`three_pt_pct`, `ft`/`fta`/`ft_pct`, `offensive_rebounds`, `total_rebounds`, `assists`, `steals`, `blocks`, `turnovers`, `personal_fouls`).

### `scripts/get_schools_list.py`

`get_schools_list(URL)` fetches a sports-reference season-stats page and parses out every `<a>` tag inside a `school_name` cell to build a DataFrame of `school`, `slug`, and `url` for each team.

Also defines `save_to_db(df, table_name, conflict_columns)`, a generic upsert helper used by every scraper in this project — it builds an `INSERT ... ON CONFLICT(...) DO UPDATE SET ...` statement from a DataFrame's columns so re-running a scrape updates existing rows instead of duplicating them.

### `scripts/scrap_one_team.py`

Empty — planned home for logic that scrapes a single team's page (likely box scores/game logs), not started yet.

### `scripts/scrape_all_teams.py`

Empty — planned home for looping `scrap_one_team.py`'s logic across every team in the `teams` table, not started yet.

### `scripts/scrape_team_stats.py`

`scrape_team_stats(url)` pulls the season-stats table off a sports-reference page with `pandas.read_html`, flattens the multi-row header into single column names (e.g. `Overall_W`), drops columns that aren't needed (`Rk`, conference/home/away win-loss splits), and renames the rest to match the `team_seasons` schema (`wins`, `losses`, `srs`, `sos`, `fg_pct`, etc.) before dropping the redundant `School` column.

### `scripts/update_all.py`

The orchestration entry point for the whole pipeline. Currently: wipes and recreates the database, scrapes the schools list and saves it to `teams`, and scrapes season stats (printing the resulting columns, but the `save_to_db` call into `team_seasons` is commented out). Games and players scraping/saving are stubbed out as comments for future work.
